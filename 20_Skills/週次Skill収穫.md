# 週次Skill収穫

## 目的
先週の作業記録（セッションログ・Inbox・LINE 受信箱・git 履歴）を読み返し、2 回以上繰り返した作業を `20_Skills/` の手順書に起こす（または既存の手順書に追記する）。人間は起こされた下書きを見て「試用中／安定」にするか捨てるかを決める。
（毎週月曜の自動タスクとして 9/20・9/22 に 2 回実行。2 回目で手順が固まったので下書き化）

## 手順
1. 先に `_Claude運用ルール.md` と `20_Skills/Skills.md`、既存の Skill ノート全部、`90_Templates/Skillテンプレート.md` を読む
2. 材料を集める
   - `00_Inbox/セッションログ/` の直近 7 日分（前回の `週次収穫-YYYY-MM-DD.md` も読み、「見送り」「次回への引き継ぎ」を確認する）
   - `00_Inbox/Inbox.md` の未チェック項目
   - `LINE/` 配下で末尾に `processed:` が無いノート（URL 1 行のみのものは Skill 材料ではなく Inbox整理 の処理待ちとして件数だけ記録する）
   - 自動タスクの成果物（`00_Inbox/SNSトレンド/`、`10_Knowledge/PC・ツール/導入候補` など）の「読めなかったソース」「手順メモ」に当たる部分
   - GitHub ミラーを `git clone` して `git log --since="8 days ago" --stat`。PC 側 Vault の方が新しいことが多いので、コミットが無ければ Vault の更新日時（device_list_dir の mtime）で代替する
3. 候補の判定
   - 「2 回以上出てきた作業」かつ「手順として書けるもの」だけを候補にする
   - 既に `20_Skills/` にあるものは新規作成せず、該当ノート末尾に `## YYYY-MM-DD` 見出しで追加情報（手順の具体化・ユーザー決定・注意）を追記する
   - 1 回しか実施記録が無いもの、方針だけ決まって実施が無いものは「見送り」にして理由を残す
4. 新規候補は Skill テンプレートの形式で `20_Skills/<名前>.md` を作る（`status: 下書き`）。目的の末尾に「いつ・何回実施して下書き化したか」を 1 行添える。`Skills.md` の表に `| [[20_Skills/<名前>|<名前>]] | 下書き | 一言 |` を 1 行追加し、frontmatter の `updated` を更新する
5. `00_Inbox/セッションログ/週次収穫-YYYY-MM-DD.md` に「読んだ材料／作成した Skill／更新した Skill／見送った候補と理由／次回への引き継ぎ」をまとめる（tags: `[session-log, skill-harvest]`）
6. `Home.md`「最近の更新」に `- YYYY-MM-DD 週次 Skill 収穫（新規N件、更新M件 → ノート名。詳細 [[週次収穫ノート]]）` を 1 行追記する
7. 既存ファイルは device_stage_files で最新を取ってから追記し、device_commit_files に `expectedMtimeMs` を付けて書き戻す。新規ファイルはそのまま commit する
8. 最後に、作成・更新した Skill ノート名と見送り候補を 3〜6 行で報告する（材料が無ければその旨 1 行）

## 注意
- 既存本文は書き換えない。追記のみ。`.claude/` 配下と `.obsidian/` は触らない。GitHub には push しない
- 機密情報（API キー、パスワード、口座番号）は書かない
- 判断に迷う候補は作らない。週次収穫ノートに「見送り」として理由付きで残せば、翌週に材料が増えてから判断できる
- Skill の状態（下書き→試用中→安定）は変えない。昇格の判断は人間が行う。自動タスクが 1 週間以上安定して走っていれば「昇格を検討」と週次収穫ノートに書くだけにとどめる
- 100 件超の LINE ノートを全部ステージングすると時間がかかる。中身が URL だけと分かっているときは、前回の収穫ノート以降の日付フォルダだけを見る
